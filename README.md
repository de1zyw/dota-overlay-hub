# Dota 2 Overlay Hub

Легальный оверлей-хаб для Dota 2: личная стата по хоткею в любой момент, поиск любого профиля
в клиенте по хоткею, разбор последнего сыгранного матча (ростер + предметы каждого). Никакого
перехвата пакетов и чтения памяти игры — только официальные/публичные источники (GSI, локальные
файлы Steam Cloud, OpenDota API, OCR своего же экрана).

**Живого ростера во время драфта — НЕТ, и это не будет починено.** Это не баг, а подтверждённое
ограничение самой Dota/Valve — см. "Известные ограничения" ниже, там разбор почему.

## ⚠️ ОБЯЗАТЕЛЬНЫЕ ПУНКТЫ (сделай это ДО первого запуска)

Пропуск любого из этих пунктов = фича молча не работает, без ошибок в логе.

1. **Установка одной командой:**
   ```bash
   cd dota_overlay
   bash install.sh
   ```
   Сам поставит зависимости, создаст ярлык в меню приложений и скопирует GSI-конфиг в папку Dota
   (если найдёт её — см. пункт 2, если нет).

2. **Steam/Dota на разных дисках (HDD+SSD, отдельный смонтированный раздел и т.п.)** —
   автопоиск смотрит все Steam-библиотеки, но если что-то пошло не так, пропиши путь руками:
   - `steam_library_override.txt` — путь до папки библиотеки, где лежит `steamapps/common/dota 2 beta`
     (например `/mnt/xxxx/SteamLibrary`), одна строка, без кавычек.
   - `steam_account_override.txt` — твой `account_id` (Steam32, не 17-значный SteamID64), если
     подсветка "это ты" не работает. Взять можно из любого лога матча (`player.accountid` в
     `GSI_PAYLOAD`) или из https://steamid.io по своему профилю.
   Оба файла проверяются ПЕРВЫМИ, до автопоиска — если файл есть и путь/id в нём рабочий, он
   используется без вопросов.

3. **Режим экрана Dota — ОБЯЗАТЕЛЬНО "Оконный полноэкранный" (Windowed Fullscreen), НЕ "Полноэкранный".**
   Настройки → Видео → Режим экрана.
   В настоящем полноэкранном (exclusive fullscreen) режиме оверлей/калибровка не могут
   рисоваться поверх игры корректно. Это ограничение Linux, не баг оверлея.

4. **Wayland-сессия (GNOME, KDE Plasma Wayland, Hyprland и т.п.)** — самое важное ограничение:
   - Прозрачные окна (оверлей, калибровка) и захват экрана для OCR требуют доступа, которого
     клиентское Wayland-приложение просто не имеет по умолчанию — в отличие от X11, тут это не
     чинится установкой композитора.
   - **Проверено вживую на реальной GNOME/Wayland-сессии (не только в теории):** захват через
     собственный D-Bus GNOME Shell (`ScreenshotArea`) реально отвечает `AccessDenied` — этот путь
     закрыт. Рабочий способ — **XDG Desktop Portal** (`org.freedesktop.portal.Screenshot`),
     на нём и «Профиль по клику», и фон калибратора теперь и построены.
   - Нужен пакет `python-gobject` (обычно уже стоит в GNOME-окружении, если нет — 
     `sudo pacman -S python-gobject`).
   - **При самом первом использовании** («Профиль по клику» или калибровка) один раз всплывёт
     системный диалог **"Allow Apps to Take Screenshots?"** — нажми **Allow**. Это разрешение
     разовое и постоянное (как доступ к камере/микрофону), дальше никаких диалогов не будет.
     Если случайно нажал Deny — включить обратно можно в Настройки → Конфиденциальность →
     Скриншоты/Экран.
   - **На других Wayland-компоситорах без такого портала** (некоторые минимальные Hyprland/Sway
     конфиги без `xdg-desktop-portal-wlr`/`-gnome`) захват всё ещё может не работать — глянь
     `logs/run_*.jsonl` на `PORTAL_CAPTURE_FAILED`/`MSS_CAPTURE_FAILED` и присылай.
   - Если есть выбор — сессия X11 при входе в систему (SDDM/GDM: значок настроек рядом с кнопкой
     входа) снимает все эти ограничения разом, но не обязательна.

5. **Для «Профиль по клику» (OCR):** нужен установленный `tesseract`:
   ```bash
   sudo pacman -S tesseract tesseract-data-rus tesseract-data-eng
   ```
   Перед первым использованием — открой любой профиль в Доте, нажми `Ctrl+Alt+R` (калибровка),
   выдели рамкой область с ником.

6. **«Разбор последнего матча» — это ПОСЛЕ матча, не во время него.** Хоткей читает локальный
   файл Steam Cloud (`last_match.dat`), узнаёт `match_id`, дальше ждёт, пока OpenDota сам
   обработает этот матч — это может занять время уже ПОСЛЕ того, как игра закончилась. Окно
   покажет "Ищу последний матч..." и обновится само, когда данные будут готовы (до 10 минут
   ожидания, дальше — сообщение попробовать позже).

## Что умеет

- **Личная статистика** (`Ctrl+Alt+S`) — работает в любой момент, не только после матча:
  ранг + бейдж лидерборда (если топ-игрок), винрейт, 10 последних матчей с KDA/GPM/XPM,
  топ-3 героя с реальным винрейтом, "часто играешь с" (частые тиммейты), и личные рекорды
  по каждому герою (лучшие килы/gpm/xpm, винстрик) — это данные, которых нет вообще нигде
  в публичном OpenDota, читаются напрямую с локального диска.
- **Профиль по клику** (`Ctrl+Alt+P`) — открой любой профиль в клиенте (друзья, реплеи,
  послематчевый экран) — OCR читает ник с экрана, ищет на OpenDota, показывает ту же стату,
  что и выше (KDA, топ-герои, но без "часто играешь с"/личных рекордов — это только для своего
  аккаунта).
- **Разбор последнего матча** (`Ctrl+Alt+M`) — полный ростер твоего последнего матча (все 10
  игроков, реальные account_id, никаких неточностей от OCR-угадывания ников), стата каждого,
  а в развёрнутом виде (`Ctrl+Alt+E`) — иконки финального билда предметов. НЕ живой — см.
  обязательный пункт 6.
- Хоткеи меняются в хабе (страница НАСТРОЙКИ).

## Источники данных

- **[OpenDota API](https://docs.opendota.com/)** — публичный, без ключа. Основной источник статы
  для всех трёх фич выше.
- **`last_match.dat`** (`~/.local/share/Steam/userdata/<account_id>/570/remote/cfg/`) — маленький
  бинарный файл (Valve Binary KeyValues), который Dota сама пишет через Steam Cloud при заходе
  в матч. Хранит только `match_id`, не ростер — сам ростер и стата приходят от OpenDota по этому id.
- **`stats.dat`** (та же папка) — личная статистика по каждому герою (винстрики, личные рекорды),
  которой нет в публичном OpenDota. Читается только для локального аккаунта.
- **Dota 2 GSI** — официальный механизм (как в CS:GO). Даёт live-данные ТОЛЬКО о локальном
  игроке во время игры (это подтверждено официальной документацией Valve) — данные о союзниках/
  врагах живьём через GSI недоступны в принципе, не только в этом оверлее.
- **OCR (`tesseract`)** — только для «Профиль по клику», читает то, что уже видно на твоём же экране.

## Запуск

Через ярлык «Dota Overlay Hub» (после `install.sh`) — или вручную:
```bash
python3 launcher.py
```
Хаб — единственная точка входа: запускает все 3 фичи в одном процессе, живёт в трее.
Повторный запуск не создаёт вторую копию — поднимает уже открытое окно.

**Демо без реальной Доты** (синтетический лог + один реальный аккаунт):
```bash
QT_QPA_PLATFORM=xcb python3 run_demo.py
```

## Структура

| Файл | Назначение |
|---|---|
| `launcher.py` | хаб — чек-листы, запуск, логи, настройки, история |
| `app.py` | связывает всё вместе — единый процесс со всеми 3 фичами |
| `config.py` | пути, хоткеи, цвета, тайминги |
| `steam_library.py` | автопоиск Steam-библиотеки с установленной Dota (+override) |
| `local_steam.py` | автопоиск локального Steam-аккаунта (+override) |
| `opendota_client.py` | статистика игрока (тротлинг/кэш/ретраи), ростер матча по `match_id` |
| `last_match_watcher.py` | читает `match_id` последнего матча из локального `last_match.dat` |
| `local_hero_stats.py` | читает личные рекорды/винстрики по героям из локального `stats.dat` |
| `lobby_watcher.py` | парсинг `server_log.txt` — **мёртвый путь, оставлен для истории/на случай если Valve вернёт формат, реально не срабатывает** (см. ограничения) |
| `gsi_server.py` | локальный HTTP-приёмник GSI-пакетов от Dota (только про локального игрока) |
| `draft_matcher.py` | сопоставление слот→герой (GSI) со слот→Steam ID (используется, только если `lobby_watcher` вообще что-то найдёт) |
| `region_calibrator.py` | drag-to-select калибровка области для OCR |
| `ocr_capture.py` | захват региона экрана + распознавание ника (tesseract) |
| `assets.py` | скачивание/кэш иконок героев/рангов/фракций/предметов/аватаров |
| `error_codes.py` | сквозные диагностические коды (`[0x1234]`/`[HTTP 429]`) в каждом сообщении об ошибке |
| `overlay_window.py` / `player_stats_window.py` | окна (PyQt, тёмная тема) |
| `hotkeys.py` / `hotkey_settings.py` | глобальные хоткеи (`pynput`) + их настройка |
| `event_log.py` | диагностический JSONL-лог на каждый запуск (`logs/run_*.jsonl`) |

## Известные ограничения

- **Живого ростера на драфте нет и не будет.** Подтверждено этой сессией разработки, не догадка:
  - `server_log.txt` в современной Dota (Source 2) **не пишется вообще** — игра говорит с серверами
    Valve через бинарный протокол Game Coordinator, а не текстовый лог. Формат, который здесь
    когда-то ожидался, — из старой (Source 1) эпохи игры.
  - GSI по официальной документации Valve отдаёт account_id/детали **только локального игрока**
    во время реальной игры — данные о союзниках/врагах просто не передаются клиенту.
  - Способ через отдельный Steam-бот (публичный протокол GC, `ValvePython/dota2`) тоже проверен и
    закрыт — нужные запросы либо отключены самой Valve на сервере, либо не возвращают данные для
    матчей в процессе (подтверждено и собственным тестом, и открытым issue у другого разработчика,
    висящим без ответа 3+ года).
  - Единственный обходной путь для "статы противника во время пика" — OCR с экрана драфта, но это
    отдельная, ещё не собранная фича со своими минусами (неточность из-за одинаковых ников).
- **Wayland**: глобальные хоткеи (`pynput`) на практике ловятся нормально (подтверждено на
  реальном матче на GNOME/Wayland) — старое предупреждение о полной неработоспособности было
  неверным. Если у тебя всё же не срабатывают — смотри `logs/run_*.jsonl` на событие `HOTKEY`.
- **Exclusive fullscreen / нет композитора** — см. обязательные пункты 3-4 выше.
- **Точный MMR** — не показывается никому, кроме своего лидерборд-номера (если топ-игрок).
  Подтверждено: Valve закрыла публичный доступ к точному MMR ещё в 2019.
- **Приватные профили** OpenDota — показываются как "профиль скрыт" (с кодом причины в скобках,
  например `[0x2001]`), это ограничение самого OpenDota/настроек игрока, не баг оверлея.

## Логи для диагностики

Каждый запуск пишет `logs/run_<timestamp>.jsonl`. Если что-то не работает — скинь этот файл
(хаб → страница ЛОГИ → "Открыть папку с логами") — по нему видно, какие события реально
происходили (хоткеи, GSI-пакеты, ошибки), без необходимости описывать словами.
