# Dota 2 Overlay Hub

Легальный оверлей-хаб для Dota 2: статистика на драфте, личная стата по хоткею в любой момент,
поиск любого профиля в клиенте по хоткею. Никакого перехвата пакетов и чтения памяти игры —
только официальные/публичные источники (GSI, `server_log.txt`, OpenDota API, OCR своего же экрана).

## ⚠️ ОБЯЗАТЕЛЬНЫЕ ПУНКТЫ (сделай это ДО первого запуска)

Пропуск любого из этих пунктов = фича молча не работает, без ошибок в логе.

1. **Установка одной командой:**
   ```bash
   cd dota_overlay
   bash install.sh
   ```
   Сам поставит зависимости, создаст ярлык в меню приложений и скопирует GSI-конфиг в папку Dota
   (если найдёт её — см. пункт 2, если нет).

2. **Steam/Dota на разных дисках (HDD+SSD, отдельный смонтированный раздел и т.п.)** —
   автопоиск смотрит все Steam-библиотеки, но если что-то пошло не так, пропиши путь руками:
   - `steam_library_override.txt` — путь до папки библиотеки, где лежит `steamapps/common/dota 2 beta`
     (например `/mnt/xxxx/SteamLibrary`), одна строка, без кавычек.
   - `steam_account_override.txt` — твой `account_id` (Steam32, не 17-значный SteamID64), если
     подсветка "это ты" не работает. Взять можно из любого лога матча (`player.accountid` в
     `GSI_PAYLOAD`) или из https://steamid.io по своему профилю.
   Оба файла проверяются ПЕРВЫМИ, до автопоиска — если файл есть и путь/id в нём рабочий, он
   используется без вопросов.

3. **Режим экрана Dota — ОБЯЗАТЕЛЬНО "Оконный полноэкранный" (Windowed Fullscreen), НЕ "Полноэкранный".**
   Настройки → Видео → Режим экрана.
   В настоящем полноэкранном (exclusive fullscreen) режиме: оверлей и калибровка рисуются чёрным
   прямоугольником вместо прозрачности, а глобальные хоткеи вообще не долетают до приложения —
   игра перехватывает клавиатуру целиком. Это ограничение Linux/X11, не баг оверлея.

4. **Нет композитора (тайловые WM — i3/dwm/bspwm без picom и т.п.)** — поставь и запусти:
   ```bash
   sudo pacman -S picom
   picom -b
   ```
   Оверлей и все прозрачные окна используют per-pixel alpha (`WA_TranslucentBackground`), это
   требует композитор. Без него — то же самое "чёрное окно", что и в пункте 3. На KDE/GNOME/Hyprland
   композитор уже включён по умолчанию, этот пункт не нужен.

5. **Для «Профиль по клику» (OCR):** нужен установленный `tesseract`:
   ```bash
   sudo pacman -S tesseract tesseract-data-rus tesseract-data-eng
   ```
   Перед первым использованием — открой любой профиль в Доте, нажми `Ctrl+Alt+R` (калибровка),
   выдели рамкой область с ником.

6. **Драфт-пики (кто что пикнул) работают ТОЛЬКО в Captain's Mode.** Это ограничение самой Dota
   GSI, не оверлея — в All Pick/Ranked/Turbo блок `draft` в GSI всегда пустой, Valve его просто
   не шлёт вне CM. Ранги/винрейты/статы команд на драфте при этом работают в любом режиме — не
   работают именно текущие пики.

7. **`server_log.txt` создаётся Dota автоматически при принятии обычного матчмейкинг-матча** —
   никаких спецопций запуска не нужно. Если после сыгранного матча файла всё ещё нет по пути
   `<библиотека>/steamapps/common/dota 2 beta/game/dota/server_log.txt` — проверь права на запись
   в эту папку (частая причина на смонтированных вручную разделах) и что матч был через обычный
   матчмейкинг с экраном принятия, а не боты/приватная лобби без accept-попапа.

## Что умеет

- **Драфт-статы** — ранг, винрейт, последние 5 матчей союзников/врагов, текущие пики (CM-only, см. п.6).
- **Личная статистика** — своя стата по хоткею `Ctrl+Alt+S`, работает в любой момент, не только на драфте.
- **Профиль по клику** — открой любой профиль в клиенте (друзья, реплеи, послематчевый экран),
  `Ctrl+Alt+P` — OCR читает ник с экрана, ищет на OpenDota, показывает стату.
- Хоткеи меняются в хабе (страница НАСТРОЙКИ).

## Источники данных

- **`server_log.txt`** — Dota сама пишет туда Match ID и Steam ID всех 10 игроков при принятии матча.
- **[OpenDota API](https://docs.opendota.com/)** — публичный, без ключа.
- **Dota 2 GSI** — официальный механизм (как в CS:GO), best-effort для текущего пика на драфте.
- **OCR (`tesseract`)** — только для «Профиль по клику», читает то, что уже видно на твоём же экране.

## Запуск

Через ярлык «Dota Overlay Hub» (после `install.sh`) — или вручную:
```bash
python3 launcher.py
```
Хаб — единственная точка входа: запускает все 3 фичи в одном процессе, живёт в трее.
Повторный запуск не создаёт вторую копию — поднимает уже открытое окно.

**Демо без реальной Доты** (синтетический лог + один реальный аккаунт):
```bash
QT_QPA_PLATFORM=xcb python3 run_demo.py
```

## Структура

| Файл | Назначение |
|---|---|
| `launcher.py` | хаб — чек-листы, запуск, логи, настройки, история |
| `app.py` | связывает всё вместе — единый процесс со всеми 3 фичами |
| `config.py` | пути, хоткеи, цвета, тайминги |
| `steam_library.py` | автопоиск Steam-библиотеки с установленной Dota (+override) |
| `local_steam.py` | автопоиск локального Steam-аккаунта (+override) |
| `opendota_client.py` | статистика игрока (тротлинг/кэш/ретраи) |
| `lobby_watcher.py` | парсинг/слежка за `server_log.txt` |
| `gsi_server.py` | локальный HTTP-приёмник GSI-пакетов от Dota |
| `draft_matcher.py` | сопоставление слот→герой (GSI) со слот→Steam ID (лог) |
| `region_calibrator.py` | drag-to-select калибровка области для OCR |
| `ocr_capture.py` | захват региона экрана + распознавание ника (tesseract) |
| `assets.py` | скачивание/кэш иконок героев/рангов/фракций |
| `overlay_window.py` / `player_stats_window.py` | окна (PyQt, тёмная тема) |
| `hotkeys.py` / `hotkey_settings.py` | глобальные хоткеи (`pynput`) + их настройка |
| `event_log.py` | диагностический JSONL-лог на каждый запуск (`logs/run_*.jsonl`) |

## Известные ограничения

- **Wayland**: глобальные хоткеи не работают (ограничение компоситора) — используй X11-сессию
  (или `QT_QPA_PLATFORM=xcb` под XWayland для рендера, хоткеи всё равно не поймает).
- **Exclusive fullscreen / нет композитора** — см. обязательные пункты 3-4 выше.
- **Драфт-пики** — только Captain's Mode, см. обязательный пункт 6.
- **Приватные профили** OpenDota — показываются как "профиль скрыт", это ограничение самого
  OpenDota (игрок сам выключил "Expose Public Match Data"), не баг.

## Логи для диагностики

Каждый запуск пишет `logs/run_<timestamp>.jsonl`. Если что-то не работает — скинь этот файл
(хаб → страница ЛОГИ → "Открыть папку с логами") — по нему видно, какие события реально
происходили (хоткеи, GSI-пакеты, ошибки), без необходимости описывать словами.
